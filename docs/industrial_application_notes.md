# 自動車 OEM / Tier1 環境への適用考察（閉域網・テナント分離・少数データ）

本書は、このリポジトリの 3 実験（[results/](../results)）から得た知見をもとに、Weight-Space Programming（WSP）を
製造業の現場、特に README で整理した自動車業界の制約下でどう使うかを考察したものです。
実験はすべて合成データ・小規模モデル・scripted 参照エージェントによるもので、実顧客データや LLM エージェントでの
検証は未実施です（[未検証事項](#7-未検証事項と次のステップ)）。

---

## 1. 前提となる制約

| 制約 | 現場で起きること | WSP が効く理由 |
|---|---|---|
| テナント間の機密データの壁・閉域網・オンプレ | 顧客データを中央に集めた再学習ができない | 修正は「重みの差分（パッチ）」として閉域網内で作れ、持ち出すのは差分だけ（Exp3 で 69 値） |
| 顧客ごとの独自ルール・ローカル記載 | 同じモデルが顧客 A では正しく顧客 B では誤る | ルールを自然言語で与え、テナント単位のパッチとして適用・撤回できる |
| きれいなペアデータがない | 学習用の正解データが少数しかない | Fix は 16 サンプル + 反実仮想プローブで校正できた（勾配 0 ステップ） |
| 迅速な PoC と定量評価 | 再学習・GPU 確保の待ち時間が長い | Exp3 の修正は CPU 上で 0.1 秒未満（順伝播 約 300 回）、Exp2 の設計変更反映は検証の再読解込みで 1 件 10 秒前後 |

## 2. ユースケース別の位置づけ

### 2.1 Read: モデル監査・資産の可読化（Exp1）

- 陰関数表現（SDF）の 3D 部品を、レンダリングや点群化なしに **重みから直接** 読み、部品種別・外形寸法・穴の
  位置/半径/貫通・止まり/ザグリまで定量的に復元できた（10 部品で種別正解率 100%、外形寸法誤差 ≈0.03 mm、
  穴半径誤差 平均 0.26 mm）。
- 現場での使い道: 受け取ったモデル（他社・他部署が作った重み）が「何を表しているか」を監査する、
  モデル資産を検索可能なメタデータ（穴径・公差・設計意図）に変換する。
- 限界: 読めるのは「ネットワークが実際に表現している形」であり、フィット誤差はそのまま読み取り誤差になる
  （ザグリ下の短い穴区間で 0.96 mm の誤差 = 学習時の表現不足）。

### 2.2 Write / Edit: 設計変更（ECN）の即時反映（Exp2）

- 平行移動・板厚変更・表面オフセットは第 1 層 / 最終層の **閉形式の重み編集**、穴の追加・拡大・縮小は
  **厳密な ReLU 部分ネットワークの書き込み + CSG 合成** で実現。7 件の ECN で、勾配 0 ステップのまま
  再学習（3,000 ステップ）と同等の Chamfer 距離（≈0.2 mm）を達成した。
- 重要な落とし穴: 学習済み SDF は真の距離場とは限らない（フランジ内径で `|∇f| ≈ 0.31`）。そのため
  「表面を 0.5 mm 盛る」をバイアス 1 つで行うと内径が約 3 倍縮む。**編集後に必ず読み直して期待寸法と比較し、
  外れた特徴だけを局所的に修復する**（verify-and-repair）ことで解消した。WSP では「書いたら読む」が必須。
- `write_from_read`（重みから仕様を読み、仕様に ECN を適用し、ネットワークを解析的に書き直す）は最も高精度
  だが、読めなかった特徴（未知の形状要素）は失われる。顧客ネットワークを残したまま差分だけ足す `wsp_edit` は
  未知要素を保存できる。両者は相補的。

### 2.3 Fix: 閉域網でのホットフィックス（Exp3）

- 症状: テナント A で学習した穴種別分類器が、テナント B で「H7 指示のあるリーマ穴」をキリ穴と誤分類
  （B のリーマ再現率 34.7% ± 16.1%）。
- 診断（すべてツールの出力に基づく）:
  1. 誤分類された B のリーマ穴でも補助ヘッド（公差検出器）は強く発火している → **能力はある**
  2. 同じサンプルの線幅だけを A のリーマ用ペン幅に変えると 3/3 がリーマに反転 → **判断は線幅（作図テンプレート）で決まっている**
  3. 融合層に一度も発火しない dead unit が 8〜13 個ある → 既存計算を壊さずに経路を足せる
- 修正: dead unit の入力重みを公差検出器の重みベクトルそのもの（`aux_tol.weight`）に、出力をリーマ +α / キリ −α に
  設定（69 値 = 全体の 0.91%）。α は反実仮想プローブで「全プローブで p(リーマ) ≥ 0.9」となる最小値の 2 倍。
- 結果: B 正解率 83.1% → 100%、B リーマ再現率 34.7% → 100%、**A の正解率 100% のまま（回帰なし）**。
  ユニットは公差トークンが無いと 0 なので、公差指示の無い入力の予測は構成上まったく変わらない。
- 対照: 同じ 16 サンプルでの少数ショット微調整（分類ヘッドのみ / 全重み）も B 正解率 99.5〜99.6% と高い。
  この規模では「勾配でも直る」のが正直な結果で、WSP の優位は **精度ではなく、変更の小ささ・説明可能性・
  回帰しないことの構成的な保証・GPU/学習基盤が不要な点** にある。

## 3. テナント分離はパッチ単位で行う

Exp3 の `wsp_route_ablate`（ドメインルール「線幅で判断してはならない」を文字どおり適用し、線幅入力を
平均値で切除）では B は 100% になる一方、**A の正解率が 83.3%（A のリーマ再現率 35.9%）に落ちた**。
A では 65% のリーマ穴が公差を別表（公差表参照）に書いており、線幅が唯一の手掛かりだったためである。

- 同じルールがテナントによって正しくも誤りにもなる。修正はグローバルなモデル更新ではなく
  **テナント単位のパッチ**（`wsp-patch/1`: 疎な差分 + 適用先ハッシュ + 理由付き編集履歴）として管理する。
- パッチは LoRA アダプタに似た「差し替え可能な差分」だが、人が読める理由・変更箇所・副作用の主張が付く点が異なる。
- 適用は `apply_patch` が適用先のハッシュを検証するので、別バージョンのモデルへの誤適用を防げる。

## 4. いつ勾配降下（FT / LoRA）を使い、いつ WSP を使うか

| 状況 | 推奨 | 根拠（本リポジトリ / 論文報道） |
|---|---|---|
| 既にある能力がボトルネック（ショートカット、ループ、偏ったバイアス）で阻害されている | **WSP（Fix）** | Exp3: 公差検出能力は存在し、経路を足すだけで回帰ゼロ。論文報道でも「本来の能力を阻害するボトルネックの除去に有効」とされる |
| 新しい知識・能力を足したい | **FT / LoRA / 再学習** | Exp3: 学習時に一度も出現しない F7 / JS7 は検出器が反応せず、経路の付け替えでは直せない（データが必要） |
| 幾何・座標系の変更（移動・スケール・オフセット・穴の追加） | **WSP（Write）** | Exp2: 閉形式・厳密な演算で再学習と同等精度、勾配 0 |
| 学習データを持ち出せない閉域網での緊急対応 | **WSP → 後で正式な再学習に還流** | パッチと監査ログを本流の学習パイプラインの入力（修正要求・反実仮想データ）にする |
| 修正の副作用を説明・保証する必要がある（品質保証・監査） | **WSP** | 変更箇所・理由・副作用の主張がパッチに残り、構成的に保証できる場合がある |
| 大規模モデルで原因箇所が分散している | **FT / LoRA（WSP は監査用途）** | 本実験は小規模・局所的な不具合のみ。大規模・分散した不具合への有効性は未検証 |

## 5. 運用フロー案（FDE / MLE 視点）

```text
1. 症状報告       現場から誤分類事例（数件〜十数件）とドメインルールを受け取る
2. 診断           エージェントが予算付きの順伝播・重み読解・反実仮想プローブで原因を特定（ツールログを保存）
3. パッチ作成     checkpoint 上で最小の編集。校正はプローブで行い、マージンを取る
4. 検証ゲート     (a) 現地 few-shot、(b) 反実仮想プローブ、(c) 既存テナントの回帰セット、(d) 変更率の上限
5. 承認           診断・編集理由・副作用の主張・数値を人がレビュー（パッチ JSON がそのままレビュー資料）
6. 適用           apply_patch（ハッシュ検証）。テナント単位で有効化・無効化
7. 監視と還流     本番の誤り率を監視し、次回の正式な再学習でパッチの意図を学習データ/目的関数へ取り込む
```

## 6. リスクと対策

| リスク | 対策（実装済み / 方針） |
|---|---|
| 少数ショットへの過適合 | 反実仮想プローブ（公差コード × 表記ゆれ）で校正し、確率マージン + 安全係数を取る（実装済み） |
| 想定外の副作用 | 構成的な保証（未使用ユニット + ReLU ゲート）、トランザクション検証、回帰セットでのゲート（実装済み） |
| LLM の誤診断・幻覚 | 主張はツール出力に紐付け、編集には理由を必須化（監査ログ）。scripted 参照エージェントとの比較 |
| 未学習トークン（能力の欠如） | 検出器の反応を先に確認し、反応しないものは「直せない」と報告（実装済み: F7/JS7） |
| サンドボックスからの逸脱 | 別プロセス + AST + rlimit + 最小環境変数。強い隔離はネットワーク無効コンテナ（`closed-net`） |
| 誤ったモデルへのパッチ適用 | 適用前後の SHA-256 検証（実装済み） |
| 距離場の性質の誤仮定（SDF） | 編集後の再読解と期待寸法の比較、外れた特徴の局所修復（実装済み） |

## 7. 未検証事項と次のステップ

- **LLM エージェントでの実行**: `--agent claude` のループとツールは実装・単体テスト済み（フェイククライアント）だが、
  本リポジトリの結果はすべて scripted 参照エージェントによる。Claude で同等の診断・修正に到達するか、
  ツール呼び出し回数・トークンコストはどれくらいかは未計測。
- **実データ**: 実際の B-Rep / メッシュ由来の SDF、実図面の VLM 特徴量、実在の公差表記ゆれ。
- **規模**: 数千パラメータのモデルのみ。Attention ヘッド単位の修正、Transformer 系の図面 VLM（プロジェクタ層・
  分類ヘッド）への適用は今後の課題。
- **SDF の学習法**: Eikonal 正則化（`|∇f|=1`）付きで学習したネットワークでは表面オフセットが直接正しくなるはず
  （未検証）。NeRF 等の重みを直接 LLM に入力するアプローチ（README で言及の Spatial LLaNA 系）との比較も未実施。
